# Design — Unité de persistance JobRecord

## Frontière

Le modèle rend les travaux persistables avant exécution selon l'exigence canonique ; il n'est pas le contrat `Job` de TECHNICAL.md §23 et ne couvre ni worker, ni transitions, ni acquisition de bail, ni politique de réessai, ni autorisation, ni déduplication active. Les valeurs sont fournies par un caller trusted ; les références ne prouvent aucune existence ni légitimité (aucune FK). `pixs.backend` est installé par les seuls harnais de test sous le label `backend` ; aucune activation de configuration production n'est introduite.

## Contrat technique

- Fichier : `src/pixs/backend/models.py` ; classe `JobRecord(models.Model)` ; imports ajoutés : `django.core.exceptions.ValidationError`, `django.core.validators.MinValueValidator`, `pixs.kernel.jobs.JobState`, `pixs.kernel.manifest.semver.parse_version` ;
- Wrapper `_validate_job_version(value: object) -> None` : refuser d'abord `type(value) is not str` avec le même message fixe ; `try: parse_version(value)` ; `except ValueError: raise ValidationError("version de travail SemVer complète attendue")` ; message fixe, aucun écho de valeur ; branché par `validators=[_validate_job_version]` sur `job_version` ;
- Champs requis : `job_id = models.TextField(primary_key=True, serialize=False)` ; `job_type`, `job_version`, `correlation_id`, `causation_id`, `perimeter_reference` : `models.TextField(blank=False)` ; `payload`, `subject`, `tenant_context` : `models.JSONField(blank=True, null=False)` (opacité interne, aucune norme de forme) ; `state` : `models.TextField(choices=[(s.value, s.value) for s in JobState], blank=False)` sans défaut ; `attempt_count` : `models.IntegerField(default=0, validators=[MinValueValidator(0)])` ;
- Champs facultatifs sans sémantique : `lease_owner = models.TextField(null=True, blank=True)` ; `lease_expires_at = models.DateTimeField(null=True, blank=True)` ;
- Meta : `constraints` = `jobrecord_job_id_non_empty`, `jobrecord_job_type_non_empty`, `jobrecord_job_version_non_empty`, `jobrecord_correlation_id_non_empty`, `jobrecord_causation_id_non_empty`, `jobrecord_perimeter_reference_non_empty` (CHECK `~models.Q(<champ>="")`, équivalent non vide avec NOT NULL, sans lookup global ajouté) ; `jobrecord_state_in_jobstate` (`models.Q(state__in=[…9 valeurs…])`) ; `jobrecord_attempt_count_non_negative` (`models.Q(attempt_count__gte=0)`) ;
- `__all__ = ["FeatureFlagSourceSnapshotRecord", "JobRecord"]` ; classe des fanions et son docstring inchangés octet pour octet ; docstrings courtes indiquant la frontière persistance seule.

## Migration

- `src/pixs/backend/migrations/0002_job_record.py` : `initial = False`, `dependencies = [("backend", "0001_feature_flag_source_snapshot")]`, unique opération `CreateModel(name="JobRecord", ...)` reproduisant exactement les champs (dont `serialize=False` sur la PK) et `options={"constraints": [...]}` ; réversible par suppression automatique ; aucun nom dupliqué, aucune opération sur la table des fanions.

## Tests

- unitaires offline (cas ciblés, `tests/unit/test_job_record.py`) : `settings.configure` minimal (`INSTALLED_APPS=["pixs.backend"]`, `USE_TZ=True`, `DATABASES` postgresql inutilisable), gardes d'interdiction de connexion (`psycopg.connect`, `PGWrapper.get_new_connection`, socket, subprocess) avec compteur `db` vérifié à zéro ; validation par `clean_fields()`/`full_clean(validate_unique=False, validate_constraints=False)` (jamais le `full_clean` par défaut) ; cas : instance complète valide ; refus état hors neuf ; refus chaque référence vide (`''`) ; refus `attempt_count < 0` et défaut 0 à la construction ; refus `job_version` non-SemVer avec message fixe sans écho ; preuve que `save()` n'appelle ni `full_clean` ni `clean` ; conteneurs JSON vides et leases None ; JSON SQL NULL refusé par la DB, la limite éventuelle de full_clean avec blank=True documentée sans promettre validation totale ; intégrité de la classe des fanions, table `backend_jobrecord`, absence de défaut sur `state`, deux noms d'export exactement ;
- intégration PostgreSQL réel (`tests/integration/test_job_record_postgres_integration.py`) : processus de test dédié chargeant PG_DATABASE/PG_USERNAME/PG_PASSWORD par la convention de loader borné existante (lecture interne ≤ 64 Kio, `stdout`/`stderr` privés, aucune valeur au modèle, au journal ni aux arguments, contrôle du répertoire racine) ; schéma d'essai unique régénérable par regex stricte d'identifiant ; forward 0001 puis 0002 dans ce schéma isolé ; roundtrip JSON réel (payload/subject/tenant) ; refus effectifs des CHECK (état hors neuf, `attempt_count` négatif, référence vide en SQL direct) ; insertion SQL directe d'un `job_version` non-SemVer ACCEPTÉE par la DB puis refus `full_clean` (limite documentée : les contraintes DB ne prouvent pas SemVer) ; reverse de 0002 seul ; vérification que les tables FeatureFlag du schéma d'origine sont inchangées ; nettoyage `finally` avec connexions fermées vérifiées ; résultat fermé `real_pg=True` après toutes les preuves, distinct du marqueur du harnais sûr ; échec de droit CREATE SCHEMA tracé en motif, sans repli simulé présenté comme preuve PG ;
- régressions minimales : cinq `py_compile` (quatre fichiers de l'unité et le harnais des fanions adapté) ; suite de base 20 modules / 111 tests ; réexécution des deux tests PG existants (fanion et connectivité) ; seule l'assertion d'inventaire de modèles du harnais fanions passe de `[FeatureFlagSourceSnapshotRecord]` à `[FeatureFlagSourceSnapshotRecord, JobRecord]`, sans affaiblir ses autres contrôles ; comptes nouveaux et suites PG existantes mesurés séparément, sans total inventé.

## Risques

- droits PostgreSQL de création de schéma dans l'environnement de test autorisé (échec tracé, jamais masqué) ; cohabitation 0001/0002 dans le schéma synthétique ; noms de contraintes PostgreSQL ≤ 63 caractères (vérifiés) ; import kernel depuis backend conforme aux précédents observés (`feature_flag_postgres_source`, `api/contracts`).
